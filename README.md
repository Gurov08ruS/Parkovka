# «ЧУЖОЕ МЕСТО»

Сервис фиксации возможных нарушений парковки на местах для людей с инвалидностью.

## Запуск тестовой версии

Нужен Python 3 и модуль SQLCipher для Python. Установка и запуск без Docker

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python backend/server.py
```

После установки сервер также можно запускать командой `python3 backend/server.py`. Она использует SQLCipher из `.venv`, если его нет в системном Python.

1. Откройте [сайт](http://127.0.0.1:8000/). Войдите с тестовым числовым ID MAX, именем и фамилией. Для повторного входа используйте тот же ID.
2. Нажмите «Сообщить о нарушении». Разрешите доступ к геолокации и камере. Сделайте один или два снимка так, чтобы на них можно было прочитать парковочный знак и госномер. При необходимости переснимите фото и добавьте комментарий.
3. Нажмите «Отправить на проверку». Обращение появится в разделе «Мои обращения» со статусом «Ожидает проверки».
4. Для проверки войдите под другим тестовым ID. В личном кабинете введите секрет из строки «Тестовый секрет проверяющего» в терминале сервера. Очередь откроется после входа.
5. Откройте обращение и измените его статус. Для отказа укажите причину. Автор увидит решение и его пояснение в истории обращения.

Сервер создаёт зашифрованную базу SQLCipher `backend/data/stukach.encrypted.sqlite3` и отдельный файл ключа `backend/data/stukach.encrypted.sqlite3.key` с правами доступа владельца. В базе хранятся профили, сессии, обращения, снимки и история статусов. Повторная отправка с тем же идентификатором запроса возвращает уже созданное обращение. Новые аккаунты видят только собственные обращения.

При первом запуске существующая база `backend/data/stukach.sqlite3` копируется в зашифрованную базу с проверкой целостности. Исходный файл остаётся на месте. Храните ключ отдельно от резервной копии базы: без него данные восстановить невозможно. Удаление исходной незашифрованной копии после проверки сохранности данных выполняется владельцем.

Для другой существующей базы укажите новый файл назначения и исходный файл. Остановите сервер, использующий исходную базу, перед переносом.

```sh
.venv/bin/python backend/server.py --db backend/data/lan.encrypted.sqlite3 --migrate-from backend/data/lan.sqlite3
```

После первого переноса запускайте сервер с тем же `--db` без параметра `--migrate-from`. Для новых файлов `--db` создаётся отдельный ключ рядом с базой.

В тестовом режиме сервер печатает новый секрет проверяющего при каждом запуске. Чтобы задать постоянный секрет, передайте его через переменную окружения `STUKACH_REVIEW_KEY`. Тестовый вход принимает введённые данные, поэтому используйте его с тестовыми профилями и материалами.

## Адрес и камера

В интерфейсе фото делается только с камеры, без выбора файла. Для поиска ближайшего адреса координаты передаются [демосерверу Photon](https://github.com/komoot/photon#demo-server) с данными OpenStreetMap. Если адрес недоступен, обращение отправляется с координатами. Чтобы переключить геокодер на другой экземпляр Photon, задайте `STUKACH_PHOTON_URL`.

«Перевернуть камеру» переключает устройство, если браузер видит несколько камер. Кнопка «Вспышка» появляется, когда камера и браузер поддерживают управление подсветкой.

Диагностика записывает время, этап и код ошибки в `backend/data/stukach.camera.log` и `backend/data/stukach.location.log`. При запуске с `--db` журналы получают имя указанной базы с расширениями `.camera.log` и `.location.log`. Снимки, координаты и данные профиля в журналы не попадают. Если браузер не смог отправить событие на сервер, оно остаётся в консоли браузера.

## Доступ по локальной сети

Подставьте IPv4 компьютера с сервером вместо `192.168.1.10`. Пример запуска использует отдельный файл SQLite для тестов по сети.

```sh
.venv/bin/python backend/server.py --host 192.168.1.10 --db backend/data/lan.encrypted.sqlite3
```

На устройстве в той же сети откройте `http://192.168.1.10:8000/`. Для доступа к камере и геолокации на другом устройстве нужно доверенное HTTPS. Для запуска с сертификатом используйте `--cert` и `--key`. На компьютере с сервером камера и геолокация доступны через `http://127.0.0.1:8000/` после выдачи разрешений. [Требования браузеров к безопасному контексту](https://www.w3.org/TR/secure-contexts/)

## Подключение к MAX

Для входа через MAX задайте `STUKACH_MAX_BOT_TOKEN` на сервере и привяжите HTTPS-адрес приложения к боту. При заданном токене сервер проверяет подпись и время выдачи `initData`, а ручной вход отключается. Тестовые профили и обращения отделены от данных, созданных после входа через MAX. Для включения кабинета проверяющего в режиме MAX задайте также `STUKACH_REVIEW_KEY`. [Документация MAX](https://dev.max.ru/docs/webapps/validation/)

Очередь предназначена для внутренней проверки. Пользователь видит её результат в разделе «Мои обращения». [План развития проекта](PLAN.md)
